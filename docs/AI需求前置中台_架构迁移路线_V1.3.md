# AI 需求前置中台架构迁移路线 V1.3

## 1. 定位校准

本项目的目标是建设 AI 需求前置分析中台，不是交付某一个库存、上下架或 ERP 自动化业务系统。库存类需求只作为端到端样例，用来验证中台能力是否能从真实材料中完成需求理解、澄清、评估和方案生成。

中台主流程为：

```text
需求/材料上传 -> 文档解析 -> 需求画像 -> AI 澄清 -> 价值/规模/风险评估 -> 产品版/技术版方案 -> 评审、版本、导出
```

## 2. 目标架构

目标架构采用同事 ReqPilot 方向的企业级技术栈，但保留当前平台已有的规则引擎、可回退 AI 编排和三档方案能力。

| 层级 | 目标选型 | 职责 | 迁移原则 |
| --- | --- | --- | --- |
| 前端 | Vue 3 + TypeScript + Vite | 中台工作台、项目、文件、澄清、方案、知识库、设置 | 先复刻当前核心页面，再增强文件/版本能力 |
| 后端 | FastAPI | 业务 API、文件解析、AI 编排、RAGFlow 适配、权限审计 | 先保持现有 Node API 语义，再逐步替换 |
| 数据库 | MySQL | 项目、需求画像、澄清答案、评估、文档版本、审计 | 从 JSON 文件迁移到关系模型 |
| 知识库 | RAGFlow + 本地文本兜底 | 文档切片、向量检索、引用来源 | RAGFlow 可开关，不阻断主流程 |
| AI 能力 | DeepSeek/OpenAI 兼容 API + 内置规则兜底 | 澄清、评估、自检、方案生成 | API Key 只在后端环境变量中保存 |

## 3. 离线与 API Key 边界

这里的“本地运行”和“完全离线”需要区分：

| 模式 | 含义 | 是否需要 API Key | 适用阶段 |
| --- | --- | --- | --- |
| 本地部署 + 云端 AI API | 前端、后端、数据库和文件在本机/内网，模型调用外部 API | 需要 | 当前最适合 |
| 内网部署 + 公司模型服务 | 平台不访问公网，只调用公司模型网关 | 需要内部密钥 | 企业上线前 |
| 完全离线 | 本地运行大模型、Embedding、Rerank 和 RAGFlow | 不需要外部 Key，但需要模型服务器 | 后续评估 |

API Key 管理规则：

1. Key 只写入 FastAPI 后端 `.env` 或部署平台 Secret。
2. 前端不保存、不回显、不通过浏览器直连模型服务。
3. MySQL 不保存明文 Key。
4. Git 不提交 `.env`。
5. API 调用失败时，保留当前内置规则引擎兜底。

## 4. 第一阶段：架构骨架，不改业务能力

目标：先让新架构能承载当前需求中台的核心流程，而不是一次性重写所有功能。

交付项：

1. 新建 `platform/` 主线目录，采用 `frontend/` 和 `backend/` 分层。
2. FastAPI 提供健康检查、设置读取、项目列表、需求详情等基础接口。
3. MySQL 初始化核心表：项目、需求画像、对话、评估、方案文档、知识库配置。
4. Vue 前端复刻当前页面骨架：工作台、新建需求、需求详情、价值优先级、设置。
5. 保留现有 Node 版本作为可运行基线，直到新架构闭环通过。

验收标准：

1. 新平台可以本地启动前后端。
2. 不配置模型 Key 时，页面和基础规则流程可用。
3. 配置模型 Key 后，可以完成一次 AI 澄清或设置页连通性测试。
4. 现有 JSON 示例数据能导入 MySQL。

## 5. 第二阶段：文件驱动需求入口

目标：吸收同事方案中最有价值的“文件上传 -> 解析 -> 需求基线”能力。

交付项：

1. 支持上传 DOCX、PDF、TXT、MD，原文件独立保存。
2. 解析结果保存为结构化文本块，保留文件名、页码/段落、表格来源。
3. 允许一个需求项目绑定多份材料。
4. 从文件内容生成初始需求画像。
5. 文件画像进入现有 AI 澄清流程，由 AI 只追问高影响缺口。

非目标：

1. 不在首期做复杂 OCR。
2. 不直接执行库存、ERP 或上下架自动化动作。
3. 不把上传文件直接当作最终方案，必须经过画像和澄清。

## 6. 第三阶段：RAGFlow 知识库接入

目标：把公司材料作为可引用背景，而不是替代业务确认。

交付项：

1. 后端 `.env` 配置 `RAGFLOW_BASE_URL`、`RAGFLOW_API_KEY`。
2. 设置页显示 RAGFlow 连接状态。
3. 知识库检索结果进入 AI 澄清、自检和技术方案生成。
4. 方案中保留来源文件名或知识片段引用。
5. RAGFlow 不可用时自动降级为本地文本检索或空上下文。

验收标准：

1. 检索 K3/E3/库存教程时能返回相关接口或 SOP 片段。
2. 技术方案引用知识库内容时标注来源。
3. 知识库内容与业务本轮确认冲突时，以业务确认优先。

## 7. 第四阶段：方案、版本和评审

目标：把当前已有三档方案能力迁移到企业级项目模型。

交付项：

1. 产品版/技术版方案继续支持初级、中级、高级。
2. 方案保存版本，记录生成时间、模型、提示词版本、知识库快照。
3. 支持文档在线预览和 DOCX 导出。
4. 支持人工确认、退回、重新生成。
5. 后续支持章节锁定和局部重生成。

## 8. 验证样例：库存类需求

库存类需求仅用于验证中台，不作为平台业务边界。验证输入包括：

1. `文档/后台库存设置教程.xls`：真实人工 SOP。
2. `文档/【2021】百胜E3标准接口文档V3.0.pdf`：E3 商品、SKU、库存、仓库接口。
3. `文档/K3Cloud WebAPI 接口说明书_V3.0.docx`：K3 单据和 WebAPI 集成方式。
4. `文档/lQLPKIH6_Zs0sOPM5s0CCLBvOh6ZmDwedAo95h12YMgA_520_230.png`：上司给出的业务目标截图。

验证中台是否能输出：

1. 结构化需求画像。
2. 高影响澄清问题。
3. 价值、规模、风险、工作量评估。
4. 带来源引用的产品方案和技术方案。
5. 明确标注“待确认”和“不可直接执行”的边界。

## 9. 建议实施顺序

| 顺序 | 工作 | 原因 |
| --- | --- | --- |
| 1 | 固化目标架构和数据模型 | 避免在 Node 旧结构上继续堆复杂能力 |
| 2 | 搭 FastAPI + MySQL 最小骨架 | 建立后端主线和 Key 安全边界 |
| 3 | 搭 Vue 工作台骨架 | 让页面承载项目/文件/方案新模型 |
| 4 | 迁移当前规则引擎和 LLM 适配 | 保留现有稳定能力 |
| 5 | 接文件解析 | 打通同事方案最有价值的入口 |
| 6 | 接 RAGFlow | 增强知识引用和技术方案可信度 |
| 7 | 做库存样例验收 | 验证中台闭环，不开发库存系统 |

## 10. 当前决策

1. 新架构可以现在启动，但不能一次性替换现有 Node 版本。
2. 现有 Node 平台作为稳定基线，直到 Vue + FastAPI + MySQL 闭环跑通。
3. RAGFlow 作为可选知识库服务接入，不能成为主流程单点依赖。
4. 平台只负责需求前置分析和方案生成，不直接执行外部业务系统动作。
5. API Key 接入是必要能力，但必须放在后端安全边界内。
